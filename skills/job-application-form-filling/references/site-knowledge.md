# Site knowledge base

本文件只记录可复用的站点差异，不记录候选人值、岗位 ID、真实申请日期、账号信息或材料原文。新条目应注明验证范围和最近验证日期；过期或改版条目应标记待复核。

## Feishu-style custom form

- **入口特征**：职位详情通常含数字岗位 ID，申请页使用自定义表单组件。
- **上传**：常见 `input[type=file]`，上传后提供解析或覆盖选项。
- **字段**：基本信息、教育、实习、项目、城市和岗位专属问题。
- **坑位**：解析后检查教育起止、项目日期/角色/链接、描述中的标题残留，以及邮箱/手机是否被清空。
- **后续岗位**：资料复用需每个站点分别验证；重点检查新增问题和意向城市。

## Moka/SugarDesign

- **入口特征**：`app.mokahr.com/campus-recruitment/...` 或同类组织路径；字段容器常带 `apply-field`/`apply-block`。
- **控件**：展示值可能在 span 中；自定义输入需要真实输入事件；年/月下拉可能倒序。
- **已知坑位**：出生日期日历、籍贯 tag-input、内层滚动、React 按钮以及未提交岗位之间的复用行为都要逐页验证。
- **审计重点**：解析后的学校/专业/学历、教育顺序、实习和项目区块、附件名。

## Zhiye/Phoenix

- **入口特征**：`<org>.zhiye.com` 或同类北森路径，流程通常分基本信息、履历、附件、预览。
- **控件**：原生 select 与自定义弹窗并存，日期格式以当前页面为准。
- **已知坑位**：异步脚本可能清空手机号/邮箱；弹窗逐条添加后必须逐条读回；真实性声明与验证码不能由自动流程猜测完成。

## Company-built form

先通过页面标签和 DOM 建立字段映射。对于 Ant Design 或其他通用组件，复用控件级方法即可，不复制另一家公司特有的选择器。任何新发现按“观察→验证→增量记录”落盘。
